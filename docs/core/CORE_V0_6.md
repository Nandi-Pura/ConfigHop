# Core v0.6 native PA-5410 QSFP targets

PA-5410 ethernet1/41–44 are conditional native QSFP targets. An engineer must select 40G or 100G. The candidate writes a direct Ethernet entry child: `<link-speed>40000</link-speed>` for 40G or `<link-speed>100000</link-speed>` for 100G. `auto` selects breakout behavior on these ports and cannot satisfy native use. Breakout children 25–40 remain blocked.

The renderer resolves the original Ethernet entry before mutation, renames it, updates or inserts one `link-speed` child, updates mapped dependencies, reparses the candidate, compares its inventory to the expected inventory, checks operation postconditions, and reverses allowed mutations for the preservation audit. The original source bytes are checked again before atomic candidate publication. Semantic diff records `SET_INTERFACE_LINK_SPEED` with the selected 40G or 100G value. Existing unknown source link-speed values remain raw in inventory.

Evidence is **DOCUMENTATION_VERIFIED** using the [PA-5400 front panel reference](https://docs.paloaltonetworks.com/hardware/pa-5400-hardware-reference/pa-5400-series-firewall-overview/pa-5400-series-front-and-back-panel-descriptions/pa-5400-series-front-panel), [Palo Alto's Mbps speed reference](https://docs.paloaltonetworks.com/ngfw/networking/configure-interfaces/configure-an-aggregate-interface-group/configure-an-aggregate-ethernet-interface), the [official PAN-OS Python SDK Ethernet path](https://github.com/PaloAltoNetworks/pan-os-python/blob/develop/panos/network.py), and its [Ethernet XML serialization test](https://github.com/PaloAltoNetworks/pan-os-python/blob/develop/tests/test_integration.py). These sources support the implementation mapping; this feature has **not** been DEVICE_VALIDATED on a physical PA-5410. ConfigHop generates a candidate, not a deployment assurance. Optics, cabling, and peer compatibility require engineer review.
