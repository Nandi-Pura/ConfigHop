# Switch backend foundation

`inspect_switch_config(text, vendor, software_family, software_version, hardware_profile_id)` parses a bounded text configuration into `SwitchConfig`. The caller selects all platform context explicitly. Inputs above 100 MiB are rejected. The result contains sorted VLANs, physical interfaces, LAGs, SVIs, static routes, basic STP intent, warnings, and vendor extensions. Conflicting declarations retain the first value and emit a warning. Undefined VLANs and LAG blocks remain visible as warnings.

The Cisco parser covers Catalyst C9300-48P with IOS-XE 17.12.x. It models the 48 base GigabitEthernet access ports; uplinks require an installed network module and are not in the profile. The HPE Aruba parser covers exact SKU JL663A (`CX 6300M 48G`) with AOS-CX 10.15, including 48 copper ports and four fixed SFP56 ports. Unknown software trains return `VERSION_NOT_VERIFIED`. Both profiles are documentation verified and analysis only.

Modeled commands include hostname, VLAN names, access/trunk VLANs, Cisco voice VLAN, administration state, interface descriptions, LAG membership and mode, SVIs, IPv4 addresses, static routes, and basic STP mode and edge intent. The parsers detect unsupported routing protocols, ACLs, policies, virtualization/stacking, authentication, DHCP snooping, ARP inspection, and Cisco private VLANs. They do not translate these features.

Official evidence: [Cisco C9300 data sheet](https://www.cisco.com/c/en/us/products/collateral/switches/catalyst-9300-series-switches/nb-06-cat9300-ser-data-sheet-cte-en.html), [Cisco IOS-XE 17.12 release notes](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst9300/software/release/17-12/release_notes/ol-17-12-9300/introduction.html), [HPE Aruba 6300M port types](https://arubanetworking.hpe.com/techdocs/hpe-central/content/get-started-with-hpe-aruba-networking-central/aos-cx-6300m-switch-port-types.html), [JL663A QuickSpecs](https://www.hpe.com/psnow/doc/a00073540enw), and [AOS-CX 10.15 applicable products](https://arubanetworking.hpe.com/techdocs/AOS-CX/10.15/HTML/fundamentals_6300-6400/Content/GPL_Abt/app-pro-all-con1.htm). Evidence is documentation verification, not device validation.

No Switch FastAPI project flow, frontend integration, semantic conversion, vendor renderer, or candidate generation is implemented. The existing Palo Alto API and hardware catalog remain separate.
